# discord-cleaner

Минималистичная CLI-тулза для удаления **собственных** сообщений в Discord:
во всех серверах, в выбранном сервере, во всех DM, в выбранном канале/DM,
или вообще везде.

> **Внимание.** Скрипт автоматизирует пользовательский аккаунт (self-bot),
> что формально нарушает [Discord Terms of Service](https://discord.com/terms).
> Возможен бан аккаунта. Используй на свой страх и риск, и предпочтительно
> на аккаунте, потерю которого ты можешь себе позволить.

## Возможности

- Меню в чёрно-белом TUI на `rich` — паста токена, выбор пункта, прогресс.
- Корректная обработка rate-limit:
  - Per-bucket трекинг по заголовкам `X-RateLimit-*`.
  - Глобальный rate-limit (`X-RateLimit-Global` + 429 `global: true`).
  - 202 от поиска по гильдии (Discord асинхронно индексирует) — ждём `retry_after`.
  - Экспоненциальный бэк-офф на 5xx и сетевых ошибках.
- Поиск сообщений:
  - В серверах — через `/guilds/{id}/messages/search?author_id=…`.
  - В DM — пагинацией `/channels/{id}/messages` + фильтр по `author.id`.
  - После каждого прохода окно из 5000 результатов сдвигается — делаем
    повторный проход, чтобы не пропустить ничего «за горизонтом».
- Сохранение прогресса в `state.json` — можно нажать Ctrl+C и продолжить
  с того же места: уже зачищенные scopes пропускаются.
- Системные сообщения и эфемерные сообщения пропускаются (их нельзя
  удалить через REST API).

## Установка

```bash
git clone https://github.com/<you>/discord-cleaner.git
cd discord-cleaner
python3 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
```

Требуется Python ≥ 3.10.

## Запуск

```bash
python main.py
```

После запуска тебя попросят вставить **user token** (ввод скрыт). Получить
его можно через DevTools → Network в веб-клиенте Discord (заголовок
`Authorization` в любом API-запросе). Никогда не отдавай токен кому-либо
и не коммить его в репо.

Дальше — меню:

```
  1. delete messages everywhere (servers + dms)
  2. delete messages in a specific channel / dm
  3. delete messages on all servers only
  4. delete messages on a specific server
  0. exit
```

## Возобновление после прерывания

Состояние пишется в `state.json` после каждого удаления. Если процесс
был остановлен (Ctrl+C, разрыв сети, перезагрузка), просто запусти
тулзу снова и выбери тот же пункт меню — будет предложено продолжить.

Чтобы начать заново, удали `state.json`.

## Логи и диагностика

- `cleaner.log` — предупреждения rate-limit, прочие API-ошибки.
- `failures.json` — каждый пропуск/неудача с разбором: `outcome`
  (`skipped`/`failed`), внутренний `reason`, код Discord `discord_code`
  и текст ошибки. Удобно посмотреть `jq '.[] | select(.outcome=="failed")' failures.json`,
  чтобы увидеть оставшиеся ошибки.

### Что значит `skipped` vs `failed`

- **`skipped`** — сообщение нельзя удалить и это ожидаемо (системное
  сообщение, эфемерное, удалённое кем-то ещё, стартовое сообщение
  форумного поста и т.п.). Тулза заранее их фильтрует.
- **`failed`** — DELETE действительно отдал ошибку, которую мы не
  знаем как обработать. Если такие появляются — пришли мне строку из
  `failures.json` (с полями `discord_code` и `discord_message`),
  расширю обработчик.

### Архивированные треды

Если сообщение лежит в архивном треде, Discord возвращает код 50083.
Тулза автоматически делает PATCH с `archived=false`, ждёт 0.5 с,
повторяет DELETE — и идёт дальше.
